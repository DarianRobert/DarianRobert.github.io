About

Engineering rigor
across every layer.

I'm a software engineer drawn to problems with more than one layer. A vision pipeline that has to survive bad lighting and a cluttered background. A model that reasons about motion over time rather than a single frame. A formal ontology that has to be both mathematically sound and machine-queryable.

My instinct is to break a system into phases, measure each one, and not trust a result I can't explain — whether that's an ablation study on a CV pipeline, a two-stage optimiser for lab scheduling, or a reasoner validating an OWL ontology from first principles.

An end-to-end pipeline for classifying complex temporal human movements from raw video. Combines CNN-based spatial feature extraction with LSTM sequence modelling — the system learns from how a motion unfolds over time, not just what a single frame looks like. The core challenge was structuring high-dimensional sequential data so the temporal signal didn't get washed out, then tuning a deep network that was actually optimizing for the right thing.

A scale- and rotation-invariant computer vision pipeline classifying South African banknotes against cluttered, highly textured backgrounds. A formal, machine-readable knowledge model establishing a shared semantic vocabulary for human analysts and automated reasoning engines. Formalises logical and mathematical relationships between cloud assets, vulnerabilities, threat actors, security controls, and compliance frameworks across IaaS, PaaS, and SaaS environments. Features over 60 logically defined classes, automated reasoning via HermiT to dynamically classify individuals, and threat & compliance mapping grounded in NIST SP 800-series, CSA CCM, and MITRE ATT&CK for Cloud. All structural relationships translated into First-Order Logic and Description Logic for mathematical soundness.

  • OWL / RDF-XML

  • HermiT 1.4.3
  • SPARQL

Solves the university lab allocation problem: assigning modules with varying enrolment sizes and software requirements to a limited pool of computer labs, minimising total unused seats. Uses a two-stage optimisation approach — a Greedy Algorithm generates a fast, feasible baseline solution respecting capacity and software compatibility constraints, then Hill Climbing Local Search iteratively improves it. Loads real lab and module data from text files, validates all constraints, and measures execution time for both stages. Built entirely on Python's standard library.
